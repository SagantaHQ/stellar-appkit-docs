Stellar AppKit ships with full internationalization support. The entire modal UI — every button label, status message, error string, ARIA label — is translatable. **English is bundled by default**; 24 additional locales are lazy-loaded via dynamic `import()` on first use, so the initial bundle stays small.

## Set the locale at initialization

Pass `locale` in the `StellarAppKit` config:

```ts
import { StellarAppKit, defaultConnectors } from '@saganta/stellar-appkit';
import '@saganta/stellar-appkit-ui-web';

const appkit = new StellarAppKit({
  network: 'TESTNET',
  locale: 'zh-CN', // ← modal renders in Simplified Chinese
  connectors: defaultConnectors(),
  appMetadata: { name: 'My App', url: 'https://app.example.com' },
});
```

English is the default — if you omit `locale`, the modal renders in English.

## Change the locale at runtime

Use `setLocale()` to switch languages on the fly. It's async because non-English locales are lazy-loaded:

```ts
import { setLocale, getLocale } from '@saganta/stellar-appkit';

// Switch to Japanese — lazy-loads the ja locale chunk
await setLocale('ja');
console.log(getLocale()); // 'ja'

// Switch back to English — instant (bundled)
await setLocale('en');
```

The modal subscribes to locale changes internally and re-renders automatically — you don't need to call any modal method.

## React hooks

### `useLocale()`

Reactive `LocaleCode` — re-renders when the locale changes:

```tsx
import { useLocale } from '@saganta/stellar-appkit-ui-web/react';

function LanguageIndicator() {
  const locale = useLocale();
  return <span>Current language: {locale}</span>;
}
```

### `useSetLocale()`

## Core API

All functions are exported from `@saganta/stellar-appkit`:

```ts
import {
  setLocale,        // (code: LocaleCode) => Promise<void>
  getLocale,        // () => LocaleCode
  t,                // (key: string, values?) => string
  onLocaleChange,   // (handler: (locale: LocaleCode) => void) => () => void
  loadLocale,       // (code: LocaleCode) => Promise<LocaleMessages>
  preloadLocale,    // (code: LocaleCode) => Promise<void>
  getSupportedLocales, // () => LocaleCode[]
  type LocaleCode,  // 'en' | 'zh-CN' | 'zh-TW' | ... (25 total)
} from '@saganta/stellar-appkit';
```

### `t(key, values?)`

Translate a key with optional ICU MessageFormat interpolation:

```ts
t('title.connect_wallet'); // → "Connect a wallet" (or translated equivalent)
t('connecting.continue_in_wallet', { walletName: 'Freighter' }); // → "Continue in Freighter"
t('siws.error_too_many_attempts', { maxRetries: 3 }); // → "Too many failed attempts (3)..."
```

You usually don't call `t()` directly — the modal calls it internally for every user-facing string. But it's exported so your app code can use the same locale system for your own strings.

### `onLocaleChange(handler)`

Subscribe to locale changes. The handler fires **immediately** with the current locale on subscription, then again whenever `setLocale()` is called. Returns an unsubscribe function:

```ts
const unsubscribe = onLocaleChange((locale) => {
  console.log('Locale changed to', locale);
  // Update your app's state, re-fetch localized data, etc.
});

// Later:
unsubscribe();
```

### `preloadLocale(code)`

Load a locale without switching to it. Useful for prefetching the user's likely-next locale (based on browser language) so the switch is instant when they click:

```ts
import { preloadLocale } from '@saganta/stellar-appkit';

// Prefetch the user's browser language at app startup
const browserLang = navigator.language as LocaleCode;
preloadLocale(browserLang).catch(() => {
  // Unknown locale — silently ignored
});
```

### `getSupportedLocales()`

Returns the 24 non-English locale codes (English is bundled, not lazy-loaded). Useful for rendering a language picker:

```ts
import { getSupportedLocales } from '@saganta/stellar-appkit';

const locales = getSupportedLocales();
// ['zh-CN', 'zh-TW', 'es', 'pt-BR', 'ja', 'ko', 'de', 'fr', 'ru', 'ar',
//  'hi', 'it', 'tr', 'pl', 'vi', 'id', 'uk', 'nl', 'th', 'he', 'cs', 'sv', 'ro', 'fa']
```

## ICU MessageFormat

Stellar AppKit uses [`intl-messageformat`](https://www.npmjs.com/package/intl-messageformat) for interpolation and pluralization. This gives you:

### Simple interpolation

```ts
// Locale string: "Continue in {walletName}"
t('connecting.continue_in_wallet', { walletName: 'Freighter' });
// → "Continue in Freighter"
```

### Pluralization

```ts
// Locale string: "{count, plural, one {# pending signature} other {# pending signatures}}"
t('connected.pending_signatures', { count: 1 }); // → "1 pending signature"
t('connected.pending_signatures', { count: 5 }); // → "5 pending signatures"
```

The plural rules are **CLDR-compliant per locale** — Arabic has 6 plural forms (zero, one, two, few, many, other), Russian has 4 (one, few, many, other), Chinese has 1 (other), English has 2 (one, other). The `intl-messageformat` library handles this automatically based on the active locale.

### Number localization

In Arabic, the `#` placeholder in plurals is localized to Arabic-Indic digits:

```ts
await setLocale('ar');
t('connected.pending_signatures', { count: 1 });
// → "١ توقيع معلق" (note the Arabic-Indic digit ١)
```

## Architecture

### English is bundled

`packages/core/src/i18n/locales/en.ts` is statically imported — no dynamic `import()`, no network request. The modal renders immediately on first load with no flash of untranslated text.

### All other locales are lazy-loaded

Each non-English locale is a separate `.ts` file in `packages/core/src/i18n/locales/`. The bundler (esbuild, webpack, vite, etc.) sees the `import('./locales/zh-CN.js')` calls in the loader registry and code-splits each into a separate chunk. Only the locale the user actually needs is downloaded.

### `IntlMessageFormat` caching

Each `(key, locale)` pair is parsed into an `IntlMessageFormat` instance once and cached. Subsequent `t()` calls with the same key + locale reuse the cached instance — no re-parsing.

### Fast path for static strings

When `t()` is called with no interpolation values, it skips `IntlMessageFormat` entirely and returns the raw message string. This is the common case (most UI strings have no variables) — the overhead is a single `Map.get()`.

### Fallback chain

If a key is missing from the active locale, `t()` falls back to English. If it's missing from English too, it returns the key itself (useful for debugging — you immediately see which key is unhandled).

Unknown locale codes (e.g., `setLocale('xx-XX')`) fall back to English silently — a wrong locale code never breaks the app.

## RTL languages

Arabic (`ar`), Hebrew (`he`), and Persian (`fa`) are RTL locales. Stellar AppKit translates the strings naturally for RTL users — it does **not** manually reverse punctuation, words, or strings. The application is responsible for handling RTL layout (CSS `direction: rtl`, flexbox order, etc.) separately.

The modal's CSS uses logical properties (`margin-inline-start` instead of `margin-left`, etc.) where possible, so it adapts to RTL automatically when the document's `dir` attribute is set to `rtl`.

## Adding a new locale

To add a locale that isn't shipped:

1. Create a `.ts` file in your app that exports a `LocaleMessages` object matching the shape of the English locale.
2. Call `loadLocale` with your custom locale, or use the lower-level `setLocale` API.

The `LocaleMessages` type is exported from `@saganta/stellar-appkit` so you get full type safety — a missing or extra key is a compile-time error.

```ts
import type { LocaleMessages } from '@saganta/stellar-appkit';
import { en } from '@saganta/stellar-appkit/i18n/locales/en';

const myLocale: LocaleMessages = {
  ...en,
  title: { ...en.title, connect_wallet: 'Connecta un portafoglio' },
  // ... override only the strings you want to change
};
```

> Note: the locale files are shipped in the npm tarball under `@saganta/stellar-appkit/i18n/locales/`. You can import the English locale directly to use as a base for custom translations.

## Performance

- **Initial bundle**: English adds ~3KB (minified) to the core package — the 24 other locales add **0KB** until `setLocale()` is called.
- **Per-locale chunk**: each lazy-loaded locale is ~2-4KB (minified + gzipped), downloaded once and cached by the browser.
- **Runtime**: `t()` with no values is a single `Map.get()` (nanoseconds). `t()` with values creates an `IntlMessageFormat` once per `(key, locale)` and caches it — subsequent calls are a `Map.get()` + `format()`.
